# HY-2D 前后端对接计划（大白话版）

## 这次要做成什么

用户以后在系统里处理 HY-2D 数据，流程应该很简单：选一个 `.tar.gz` 数据包，填几个处理参数，点“开始处理”，看进度，处理结束后下载结果，必要时把轨迹和异常点放到地图上看。

这不是把 HY-2D 当卫星影像来处理。它是一串沿着卫星轨道采集的观测点，所以界面要说“沿轨”，不能说“多波段融合”或“图像显著性”。

## 用户实际会怎么用

1. 在“多源卫星数据处理”里选择“HY-2D 雷达高度计 IDR 2MC”。
2. 页面只让他上传一个 `.tar.gz` 包，不需要自己解压、挑 `.nc` 文件或上传 XML。
3. 用户填三个主要参数：用多少个点算一个窗口、MAD 异常阈值、相邻点跳变阈值。还可以选择是否生成统计网格。
4. 页面把文件和参数发给后端。后端先检查这是不是受支持的 HY-2D 包，再创建任务，然后按照既定的八个步骤执行。
5. 页面每隔几秒问一次后端：任务做到哪一步了、有没有失败、已经生成了哪些最终结果。
6. 成功后，用户可以下载总 ZIP，也可以单独下载 GeoJSON、CSV、NetCDF、Parquet、COG 和结果摘要。
7. 用户点“在地图查看沿轨结果”后，页面从后端取两份最终 GeoJSON：一份画轨迹线，一份画异常点。

## 八个步骤在做什么

| 系统步骤 | 大白话 |
| --- | --- |
| 校验产品包 | 看压缩包里有没有系统需要的 NetCDF 和元数据。 |
| 解析沿轨观测 | 把原始数字、缩放系数和空值读成能计算的数据。 |
| 质量过滤 | 把明确不可靠的观测先筛掉，并留下原因。 |
| 计算工程基线 SSH | 按当前已经确定的工程公式算海面高度相关结果。 |
| 提取沿轨特征 | 看每一小段轨迹的均值、波动、变化趋势等。 |
| 检测沿轨异常 | 用 MAD、突然跳变和绝对值规则找出可疑点。 |
| 生成标准结果 | 输出可以下载和复用的标准沿轨文件。 |
| 生成统计网格（可选） | 把有效观测按格子做统计，不补点、不插值。 |

## 前后端各自负责什么

前端只做用户能看到和能操作的部分：选产品、选文件、填参数、显示进度、显示错误、提供下载、在地图上画轨迹和异常点。

后端负责真正干活和安全：检查文件、安排八个步骤、调用 Python 算法、校验算法输出、把最终文件保存起来、判断谁有权下载。Python Worker 不直接把磁盘路径交给前端，也不决定最终文件存在哪里。

这条分工很重要。前端只知道“任务 101 的异常 GeoJSON 可以下载”，不应该知道“服务器 D 盘哪一个目录有文件”。这样既安全，也方便将来从本地磁盘换成对象存储。

## 为什么先改接口，再改页面

现在后端进度接口还会返回内部文件地址。页面如果先拿这个地址做下载或地图展示，短期看似能跑，后面会留下安全问题，也会把前端绑死在服务器目录结构上。

所以第一步是让后端只给页面安全的信息：产物类型、文件名、文件大小、校验和、是不是可以下载，以及失败原因。真正下载时，页面只带“任务编号 + 产物类型”请求后端。后端确认这个人有权限、这个产物是最终产物，才把文件给他。

## 哪些结果能下载，哪些不能

能下载的是最终结果，例如：标准沿轨 NetCDF、CSV、Parquet、轨迹 GeoJSON、异常 GeoJSON、摘要 JSON，以及可选的统计网格文件。

不能下载的是中间文件，例如原始解码结果、质量过滤临时结果和 Worker 的临时清单。这些文件只给后面的算法步骤使用，用户既不需要看，也不应该看到。

## 地图这次做到什么程度

这次地图只做两件可靠的事：画完整轨迹，标出异常点。用户点异常点时，可以看到时间、位置、异常类型、数值和阈值等公开信息。

统计网格 COG 这次先允许下载和看摘要，不直接贴到 Cesium 地图上。因为把 COG 正确地放到地图上需要额外的受权限控制的切片服务；直接让浏览器去读服务器文件不安全，也不稳定。以后有专门的 COG 地图服务，再单独接这一项。

## 页面上必须一直提醒的事

当前质量规则、SSH 改正和绝对 SSH 阈值，是根据现有数据和工程实现建立的基线，还没有完整官方 IDR/IGDR 说明可以最终确认。因此页面要明确写“工程基线，需按官方规范复核”。

这不表示结果不能用，而是表示它适合做系统流程验证、质量排查和后续比对，不能被包装成官方科学产品，更不能直接当成最终权威结论。

## 开发人员做完后，怎么判断对不对

- HY-2D 只接受一个 `.tar.gz` 包，错误文件不能开始处理。
- 窗口必须是大于等于 3 的奇数，两个阈值必须大于 0；启用统计网格时，网格大小必须在 0 到 5 度之间。
- 页面能显示八个步骤的中文名字，失败时能说清在哪一步失败，并能在允许时重试或取消。
- 页面能逐个下载最终结果，也能下载总 ZIP；中间结果没有下载入口。
- 页面、浏览器请求和后端响应里都看不到服务器文件路径、Worker 临时目录或 manifest。
- 地图能画轨迹和异常点，不会清掉系统里原本存在的其他地图图层。
- 开启统计网格后，页面写的是“统计网格”，不会说成“插值影像”。
- 工程基线待复核提示在参数区和结果区都能看到。
- Java 后端测试、Python 算法测试、前端类型检查和前端构建全部通过，再交付。

## 推荐的实际顺序

先让后端把安全接口做好，再让前端增加 HY-2D 产品和参数，再改通用任务流程，再做进度下载页面，最后接地图和真实数据联调。这样每一步都能独立检查，也不会为了赶页面而把服务器路径或中间文件暴露出来。

官方 IDR/IGDR 格式说明以后拿到后，要另开一次“科学规则复核”：核对质量位、SSH 改正项、阈值和网格规则。那是更新科学规则，不是重做这次前后端对接。
