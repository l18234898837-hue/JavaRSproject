# GF6 WFV L1A 前端替代计划（大白话版）

## 这次到底要改什么

现在页面是旧的 Browse 流程：让用户上传 JPG、JGW、JSON 三个文件。这个流程在前端要完全下线。

改完以后，用户打开“多源卫星数据处理”，只能看到“GF-6 WFV L1A 工程处理”。页面不再让用户选择产品类型，也不再出现 JPG、JGW、JSON。

注意：这里只是把**前端入口**完全替换掉。后端里原来的 Browse 代码和历史数据不要求删除，避免影响已经存在的任务。

## 用户以后怎样操作

1. 上传三块 TIFF。
2. 上传 XML、RPB、NAV、TIL。
3. 有足迹文件时，同时上传 SHP、DBF、SHX；没有就三个都不传。
4. 页面自己检查文件格式、文件名是否属于同一个产品、文件是否齐全。
5. 设置分辨率、裁剪范围、波段、特征、融合、显著性。
6. 点击开始，页面先让后端检查产品，再创建任务。
7. 页面显示处理进度：拼接、定标、RPC、配准、裁剪、标准结果、特征、融合、显著性。
8. 失败时可以重试，处理时可以取消。
9. 成功后下载 ZIP。

## 这次不要做什么

- 不保留前端的 Browse 产品选项。
- 不让用户选择 DEM、正射校正、大气校正或任意算法。
- 不把电脑本地路径、Worker 内部文件、RPC 系数显示在页面。
- 不做地图预览和整景影像浏览。
- 不承诺定位精度，也不把显著性说成目标识别。

## 文件为什么不能简单比较名字

真实产品里三块 TIFF 的名字会是：

```text
产品名-1.tiff
产品名-2.tiff
产品名-3.tiff
```

其他 XML、RPB、NAV、TIL 都是：

```text
产品名.xml
产品名.rpb
产品名.nav
产品名.til
```

所以前端校验时要先去掉 TIFF 的 `-1/-2/-3`，再比较“产品名”。这块必须写自动化测试，否则很容易把正确的三块 TIFF 误判成不同产品。

## 要做的 8 件事

### 1. 先加前端测试能力

当前项目只有类型检查和构建，没有专门跑前端单元测试的命令。先加一个很小的测试入口，后面每一块修改都要先写失败测试。

### 2. 把三文件模板换成十文件模板

固定十个槽位：

- TIFF 1、TIFF 2、TIFF 3：必须
- XML、RPB、NAV、TIL：必须
- SHP、DBF、SHX：可选但必须成套

旧 JPG、JGW、JSON 代码从前端公共类型和页面里移除。

### 3. 把处理参数固定下来

页面要有：分辨率、0 米固定高程、ROI、八个波段、特征、融合、显著性。

点击开始时，这些参数会被打包成一个固定格式的 JSON。任务创建后不能偷偷改变。页面不提供 DEM 和“高程模式”选择。

### 4. 前端和 Java 说同一种语言

前端需要 Java 明确告诉它：这是不是 `GF-6-WFV-L1A/v1` 产品、任务到了哪个阶段、哪些结果可下载。

前端不能再从任务名称猜产品类型，也不能只看 packageId 的开头。Java 必须返回明确的 `productCode` 和 `profileVersion`。

### 5. 重写任务状态机

当前状态机固定为三个 Browse 文件。要改成十个 L1A 槽位，并确保：

- 少一个必需文件就不能检查。
- 预检只接受唯一的 L1A 产品。
- 创建任务时发送 L1A 参数，不发送旧 Browse 默认参数。
- 任务结束、取消、重置、替换文件、关闭页面时，轮询必须停止。

### 6. 重写整个页面

页面顶部不再有产品下拉框。文件区域后面是参数区域，然后是任务状态和下载区域。

页面始终提示：

- 当前是无 DEM 的名义 RPC。
- 定位精度尚未验证。
- 如果启用显著性，结果只是候选区域，不是识别结论。

### 7. 把错误和结果说清楚

用户应该能看到“产品文件不完整”“ROI 不相交”“参数不对”等中文，而不是后端堆栈。

页面只展示允许下载的最终结果，不显示中间拼接文件、临时 VRT、内部 URI 或本地路径。

### 8. 真实数据验收

用当前 GF6 数据上传一次，先选小 ROI。检查能否从上传走到下载。

再试错：传 JPG、少 TIFF、文件名不一致、只传 SHP、ROI 放到影像外、取消任务、失败重试、没完成就下载、不是任务本人下载。

## 开发完成的证据

开发人员最后必须提供：

```text
pnpm test:unit      通过
pnpm typecheck      通过
pnpm build          通过
真实小 ROI 上传到下载 通过，或明确写出 Java 接口还缺什么
```

不能只说“页面看起来能用”。每一步都要先有会失败的测试，再有通过的测试。

## 验收时最容易漏的地方

- TIFF 的 `-1/-2/-3` 要正确识别为同一个产品。
- SHP/DBF/SHX 不能只传一部分。
- 三块 TIFF 上传给后端的顺序必须是 1、2、3。
- 前端完全不再显示 Browse 文件或产品名称。
- 无 DEM、未验证、候选显著性三条限制必须显示。
- 终态后页面不继续轮询。
- ZIP 里不能出现原始 TIFF、临时文件、电脑路径或 RPC 系数。

## 最后能对外说什么

只能说：“GF6 WFV L1A 前端入口已经替代旧 Browse 前端，并完成从上传到最终结果下载的工程任务闭环。”

不能说已经完成 DEM 正射校正、绝对定位精度认证、官方产品认证、目标识别或变化检测。
