# FY-4B AGRI 前端对接计划：大白话核对版

这份文件不讲代码怎么写，只讲最终页面应该怎么用、每一步应该发生什么，以及你可以怎样判断对接是否正确。

## 一、这次要做什么

现在页面里已经有一个“多源卫星数据处理”区域，但原来主要是给 GF-6 使用的。接下来要在同一个区域中增加 FY-4B AGRI，不另起一套孤立页面。

用户最终要能够完成这条流程：

```text
选择五个系统文件
    -> 检查五个文件是否属于同一组 FY-4B 数据
    -> 选择处理参数
    -> 创建处理任务
    -> 让服务器按顺序执行处理阶段
    -> 查看处理进度
    -> 必要时取消或重试
    -> 成功后下载最终结果 ZIP
```

## 二、用户要选择哪五个文件

必须选择同一次观测的五个已经登记到系统中的文件：

1. 500 米 FDI 文件
2. 1000 米 FDI 文件
3. 2000 米 FDI 文件
4. 4000 米 FDI 文件
5. 4000 米 GEO 文件

这五个文件的卫星、起止时间、版本必须一致。FDI 文件不能拿 GEO 文件代替，分辨率也不能混用。

页面提交给后端的不是电脑上的文件路径，而是系统文件记录的 ID。例如页面列表中某个文件的 `id` 是 `12345`，前端只能提交这个 ID。像 `D:\data\FY4B\xxx.HDF` 这样的路径不能出现在请求中。

如果缺少一个文件、选错分辨率、时间不一致、版本不一致，页面应明确告诉用户原因，并禁用开始按钮。后端预检仍然是最后的权威检查，前端提示不能代替后端校验。

## 三、参数页面应该让用户做什么

参数页面只显示确实支持的选项：

- 目标坐标系：`EPSG:4326` 或 `EPSG:4490`
- 区域裁剪：可关闭；开启后填写最小经度、最小纬度、最大经度、最大纬度
- 特征提取：可关闭；可选统计、梯度、局部方差、近红外红边指数、热红外亮温差等指标
- 近红外伪彩色融合：可关闭；使用固定的 `NIR_RED_BLUE` 模式和百分位范围
- 显著性检测：可关闭；选择检测来源、阈值和奇数窗口大小

输入不合法时，页面应在提交前阻止请求，例如：

- 经度超过 `-180` 到 `180`，纬度超过 `-90` 到 `90`
- 最小值大于或等于最大值
- 局部方差或显著性窗口不是大于等于 3 的奇数
- 融合百分位不在 0 到 100 之间，或低值不小于高值
- 开启特征却没有选择任何指标
- 显著性选择了某个特征，但特征提取没有自动开启

如果显著性选择“梯度”“局部方差”“近红外红边指数”或“亮温差”，页面要自动补上对应的特征选项，不应要求用户自己理解这个依赖关系。

即使用户关闭特征和融合，提交给后端的内容也必须是合法的默认结构，不能发送空数组、缺字段或 GF-6 专用字段。

## 四、点击开始后应该发生什么

点击“预检并开始”后，页面按以下顺序工作：

1. 前端先检查五个文件和参数。
2. 前端调用预检接口，确认后端识别出 `FY-4B-AGRI/v1`。
3. 后端返回一次性的预检凭证和候选 ID。
4. 前端使用这次预检返回的凭证创建任务。
5. 前端请求后端调度下一个可以执行的阶段。
6. 前端定期查询任务进度。
7. 当前阶段完成后，再调度下一个阶段，直到任务成功、失败或取消。

预检凭证不能跨文件或跨任务重复使用。用户更换任意文件或参数后，旧的预检结果必须失效并重新预检。

页面同一时间最多只能发出一个调度请求。轮询失败可以在退避间隔后再次请求，但不能因为网络重试而重复启动同一个阶段。

## 五、进度页面应该显示什么

阶段名称要翻译成用户看得懂的中文，例如：

- 验证 FY-4B 五文件包
- 构建名义静止卫星网格
- 辐射定标与名义定位
- 重投影与区域裁剪
- 生成标准 COG
- 提取特征
- 生成近红外伪彩色
- 显著性候选检测

状态至少要能显示：等待执行、排队中、执行中、已完成、失败、恢复中、取消中、已取消。后端以后增加新状态时，页面显示“未知状态”即可，不能白屏或报错。

每个阶段可以显示执行状态和尝试次数。失败阶段只有在后端允许重试时才显示“重试”按钮。取消操作需要用户确认；取消后页面继续刷新，直到后端确认任务已取消。

任务进入成功、失败或已取消后，页面必须停止继续轮询。离开页面或切换产品时，也必须清理定时器。

## 六、结果下载应该是什么样

任务成功后，页面显示“下载全部最终结果 ZIP”。任务未成功时，这个按钮必须不可用。

ZIP 中可能包含：

- 标准 COG
- 质量 COG
- 标准处理摘要
- 用户开启后生成的特征结果
- 用户开启后生成的伪彩色结果
- 用户开启后生成的显著性结果

用户不需要也不应该看到服务器目录、中间 NPZ、Worker 临时文件、manifest 或内部 URI。前端不能根据 URI 自己拼下载地址，当前阶段统一使用后端提供的 ZIP 下载接口。

## 七、你可以怎样判断前端做对了

让开发人员用真实 FY-4B 五文件走一遍，并逐项核对：

1. 能选中五个正确角色，页面能显示文件名和角色。
2. 少一个文件或混入错误文件时，开始按钮不可用，并显示具体原因。
3. 正确文件通过预检，候选显示为 FY-4B AGRI 对应版本。
4. 创建任务时请求里只有五个系统文件 ID、预检凭证、候选 ID 和合法参数字符串。
5. 请求里没有电脑路径、Worker 命令、输出路径、执行 ID 或内部存储地址。
6. 页面只发出一个调度请求，不会重复启动同一阶段。
7. 阶段状态能持续更新，任务结束后不再产生轮询请求。
8. 取消和重试按钮只在对应状态下出现。
9. 只有成功任务可以下载 ZIP。
10. 页面和浏览器 Network 内容中都找不到 `storageUri`、`storageKey`、服务器盘符路径、manifest 和临时目录。
11. 开启特征、融合、显著性后，进度和最终 ZIP 中出现对应结果；关闭后不应凭空出现这些结果。
12. `pnpm test:unit`、`pnpm typecheck` 和 `pnpm build` 均通过。

## 八、哪些事情不是前端做的

前端不负责自己计算导航、投影、定标、重投影、裁剪、COG 或显著性算法。前端只负责收集合法输入、调用后端接口、展示后端状态和下载最终结果。

前端也不负责海岸线控制点残差计算、云检测或分类，这些功能不应出现在本次页面中。

FY-4B 真实 500 米全圆盘完整产物是否成功生成，必须以实际后端和 Worker 资源为准。如果电脑资源不足，只能记录“前端请求链路已联调，完整产物未完成验收”，不能把页面请求成功误说成算法结果已经验收。

## 九、最终一句话判断标准

用户只需要选择五个系统文件、设置允许的参数、点击开始并等待结果；页面能够安全、准确地告诉用户处理到了哪一步，并在成功后下载 ZIP，同时完全不暴露服务器内部路径和实现细节，这就说明前端对接达到了本次目标。
