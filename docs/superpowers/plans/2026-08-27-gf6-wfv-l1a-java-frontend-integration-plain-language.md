# 历史内容（仅供追溯）

目标很简单：用户把 GF6 的文件选好并上传，系统能检查文件、创建任务、显示处理进度，最后让用户下载结果。已经完成的 Worker 算法不重写，这一轮只把 Java 后端和前端接起来。

## 先说结论

当前页面还是“GF6 浏览产品”流程，只支持 JPG、JGW、JSON 三个文件。GF6 L1A 实际需要三块 TIFF、XML、RPB、NAV、TIL，另外还可能有 SHP、DBF、SHX。因此不能只改一个按钮，必须把文件选择、参数、后端任务和下载一起改完。

## 用户最后会怎么用

1. 打开多源卫星数据处理页面。
2. 选择“GF-6 WFV L1A”。
3. 依次选择三块 TIFF、XML、RPB、NAV、TIL；如果有足迹文件，再选择 SHP、DBF、SHX。
4. 页面检查文件格式、产品编号是否一致、必需文件是否齐全。
5. 点击“检查文件”，后端调用 Worker 判断是不是完整的 GF6 L1A 产品。
6. 选择目标坐标系、分辨率、ROI、波段、特征、融合和显著性参数。
7. 点击“开始处理”。
8. 页面显示拼接、定标、RPC、配准、裁剪、标准 COG 等阶段。
9. 失败时显示人能看懂的原因，并允许重试失败阶段；处理中的任务可以取消。
10. 成功后下载 ZIP，里面只有最终结果和摘要，不放原始 TIFF 或内部临时文件。

## 需要开发的 9 块内容

### 1. 先把双方说法统一

Java、Worker、前端必须统一使用：

- 产品：`GF-6-WFV-L1A/v1`
- 参数版本：`gf6-wfv-l1a-v1`
- 文件角色：三块 TIFF、XML、RPB、NAV、TIL，SHP/DBF/SHX 可选
- 阶段名称：拼接、定标、RPC、配准、裁剪、标准 COG、特征、融合、显著性

先写测试证明这些名字一致，再写代码。否则最容易出现前端传了一个名字、Java 等另一个名字、Worker 又等第三个名字的问题。

### 2. 让 Java 真正认识 GF6 L1A

数据库里增加独立的 GF6 L1A 产品 profile，不要拿 Browse profile 凑合。预检时必须能返回唯一的 GF6 L1A 候选，同时保证原来的 Browse 产品还能正常使用。

### 3. 让 Java 知道每个阶段该拿什么文件

Java 要明确：

- 拼接阶段拿三块 TIFF 和 TIL。
- 定标阶段拿拼接结果和 XML。
- RPC 阶段拿 XML、RPB、NAV。
- 后面的裁剪、标准 COG、特征、融合、显著性只能拿前面已经生成并登记的结果。

如果某个阶段想读取没有声明的文件，Java 要在调用 Worker 前拒绝。

这里还有一个必须先补上的接口问题：现在 Worker 的计划结果只有“阶段名称和依赖关系”，没有完整写出每个阶段需要哪些输入、会产生哪些输出、使用哪个参数快照。要先把 Worker 的计划结果补成完整格式，再让 Java 翻译和授权；不能让 Java 自己猜。

### 4. 让 Java 安全地登记和下载结果

处理结果要记录类型、大小、SHA-256、是否最终结果、是否允许下载。用户只能下载自己任务的最终结果，不能下载别人的任务，也不能下载中间文件。

ZIP 里只放最终 COG、摘要 JSON、显著性 score/mask 等最终产物，不放原始三块 TIFF、VRT、Worker manifest、RPC 系数、授权 token 或电脑上的真实路径。

### 5. 把前端三文件选择器改成 L1A 文件选择器

现在前端是 JPG/JGW/JSON 三个槽位，要改成：

- TIFF 1
- TIFF 2
- TIFF 3
- XML
- RPB
- NAV
- TIL
- SHP（可选）
- DBF（可选）
- SHX（可选）

页面要明确提示缺哪个文件、哪个扩展名不对、三个 TIFF 是否来自同一个产品。SHP、DBF、SHX 如果只传其中一部分，也要提示用户补齐或全部不传。

### 6. 把参数和任务流程接起来

前端表单增加：

- 目标坐标系，默认 `EPSG:4326`
- 分辨率，默认 `0.00015`
- RPC 高程，固定模式，默认 0 米
- ROI，可不填
- B1 到 B8 选择
- 特征开关和特征类型
- RGB 融合开关及红绿蓝波段
- 显著性开关、来源波段、窗口大小、阈值

点击开始后，前端必须把这些值组成一个版本化 JSON，并交给 Java 冻结。不能继续发送原来 Browse 产品的默认参数。

### 7. 把状态和限制显示出来

页面要显示每个阶段的状态：等待、运行、成功、失败、取消、等待恢复。错误提示使用稳定中文：文件不完整、ROI 不相交、参数错误、授权过期、Worker 失败等。

页面必须一直说明两件事：

- RPC 是没有 DEM 的名义校正，定位精度还没有验证。
- 显著性结果只是候选结果，不等于目标识别或变化检测。

### 8. 做 Java 和前端联调测试

用小型合成文件模拟完整流程，检查：

- 文件上传和角色是否正确
- 预检是否返回唯一候选
- 参数快照是否正确
- 阶段是否按依赖顺序运行
- 失败阶段是否能重试
- 任务是否能取消
- 成功后是否能下载
- 错误用户是否不能下载

这一步不需要把真实 13.5GB 数据放进自动化测试。

再专门测试错误情况：少一个 TIFF、ROI 放到影像外、错误扩展名、取消、失败重试、过期检查、别人下载。

## 每块完成的标准

每一块都不能只说“代码写完了”，必须有：

1. 一个会先失败的测试。
2. 实现后测试通过。
3. 相关旧测试没有被破坏。
4. 一次独立提交。
5. 提交中不包含真实大文件、临时文件和电脑本地路径。

## 最终必须看到的结果

用户不需要了解 Worker，也不需要知道文件放在电脑哪个目录。用户只负责选文件、填参数、点击按钮和下载结果。系统负责检查文件、按顺序处理、显示进度、报告失败、保护结果下载权限。

但最终对外只能说“工程处理闭环完成并通过专项验收”，不能说已经完成 DEM 正射校正、绝对定位精度认证、官方产品认证、目标识别或变化检测。
