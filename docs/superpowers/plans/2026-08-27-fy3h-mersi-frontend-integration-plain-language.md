# FY-3H 前端对接计划，大白话核对版

## 这件事到底要做什么

现在系统后端已经能处理 FY-3H MERSI 的一对文件：一份 `1000M` 观测 HDF，加一份 `GEO1K` 定位 HDF。前端现在只会处理 GF-6 的三份文件，所以需要让现有“多源卫星数据处理”页面多认识一种产品，而不是再造一个新页面。

用户最终应该能这样操作：

```text
在左侧“多源卫星数据处理”页
  -> 选择“FY-3H MERSI-III L1（1000M + GEO1K）”
  -> 选一份 1000M HDF 和一份 GEO1K HDF
  -> 选波段和可选算法参数，或保持默认
  -> 点击开始处理
  -> 看见每一步处理到哪里了
  -> 成功后下载标准 COG、质量 COG、摘要和可选结果
```

## 用户在页面上应该看到什么

### 1. 产品选择

原先的 GF-6 选项必须继续保留。多一个 FY-3H 选项后，页面只显示 FY-3H 需要的两个上传框：

```text
1000M 观测文件（.HDF）
GEO1K 定位文件（.HDF）
```

两个文件都要上传成功才能点开始。用户把文件放错框、选成不同时间、不同版本，页面要在开始前告诉他哪里不对。

这里的文件名检查只是“早点提醒”。真正检查卫星、传感器、时间、轨道、版本、尺寸的工作，还是后端做。也就是说，前端通过不等于后端一定通过。

### 2. 参数区

默认情况最简单：全球经纬度网格、`0.01` 度分辨率、25 个波段、不开启可选算法。用户只要两个文件正确，保持默认就能开始。

有高级需要时，用户还可以：

```text
限制处理范围（ROI）
挑选 1 到 25 波段
做特征提取
做 RGB 融合
做显著性检测
```

页面要帮忙拦住明显错误：

```text
RGB 不能拿 20 到 25 热红外通道做颜色通道。
局部方差和显著性窗口必须是至少 3 的奇数。
低百分位必须小于高百分位。
显著性来源只能选当前波段或已经启用的特征，不能自己随便写名字。
```

页面不应该让用户填写定标系数、质量位、Worker 文件路径、任意 CRS 文字或双线性插值。这些不是普通用户的参数，且后端当前也没有允许它们。

### 3. 处理进度

用户会看到这些中文步骤，而不是难懂的内部键名：

```text
校验 1000M 与 GEO1K 配对
解码 MERSI L1 数据
执行 25 通道物理定标
生成质量掩膜与统计
按逐像元定位网格化
生成标准 MERSI COG
提取可选特征
生成 RGB 融合产品
生成显著性产品
```

没有启用的可选算法步骤不会出现。失败时要告诉用户失败在哪一步和后端给出的公开错误信息；可以重试的步骤才显示重试按钮。点击取消后不能马上假装已经取消，必须等服务器回报 `CANCELED`。

### 4. 下载结果

成功后至少能看到并下载：

```text
标准科学 COG
质量掩膜 COG
处理摘要 JSON
```

启用了可选算法时，可能还会有特征、RGB 融合、显著性评分和显著性掩膜等 COG 或摘要。

用户可以下载单个最终文件，也可以下载全部最终结果 ZIP。用户绝对不应该看见或下载：

```text
中间 NPZ
临时质量文件
rs:// 形式的 URI
服务器目录
Worker work 目录
asset manifest
```

这不是为了“藏起来”，而是因为这些内部地址不稳定，也不能授权给浏览器。

## 为什么还要改一点 Java 后端

当前进度接口会把内部 URI 发给前端，ZIP 也可能把中间文件打进去。这对真正上线不合适，所以必须先做一个小的后端收口：

```text
进度接口只给文件类型、大小、校验和、文件名、是否可下载。
前端下载一个文件时只说“任务号 + 产物类型”。
后端确认这个任务属于当前用户、这个文件是最终产物，才把文件流给浏览器。
ZIP 里只放最终产物。
```

这样前端可以安全显示和下载，也不会因为知道某个 URI 就能猜到别人的结果。

## 给接手开发人员的执行顺序

```text
第 0 步：确认后端已合入 FY-3H，现有测试是绿的。
第 1 步：后端先把进度、详情、下载接口改成安全版本并测试。
第 2 步：前端加测试工具，做 FY-3H 两文件模板和参数检查。
第 3 步：把原来只认识 GF-6 的通用任务逻辑改成按模板工作。
第 4 步：把 FY-3H 的上传框、参数、进度、结果下载放进现有页面。
第 5 步：用真实 2335 样例跑一遍正常流程，用 2350 样例看异常提示。
第 6 步：跑 Java、Python、前端全部测试，写联调记录。
```

每一步都要先写能失败的测试，再写代码让它通过。不要一边改很多文件一边靠手工点页面猜对不对。

## 什么算完成

下面这些都满足，才算前端对接完成：

```text
GF-6 没被改坏。
FY-3H 双 HDF 能正常上传、预检、创建任务、启动和轮询。
默认参数可以跑通；可选特征、RGB、显著性也能跑通。
用户只能下载最终结果。
页面和网络响应里没有服务器路径或内部 URI。
2335 能得到标准 COG、质量 COG、摘要。
2350 的定位异常不会被页面说成“完全正常”。
所有 Java、Python、前端自动化检查都通过。
```

## 这件事完成后，仍然不能宣称什么

FY-3H 后端里仍明确标着“定标公式需要人工对照官方 PDF 复核”。所以即使前端能完整跑通、下载结果，页面也必须保留这个提示：

```text
处理成功只说明软件流程执行成功；不代表官方公式人工复核已经完成，也不代表结果已经获得官方科学认证。
```

另外，本次不做地图直接预览 COG。先把文件正确、安全地交给用户下载；以后若要在地图上看 COG，需要另做安全的影像服务或瓦片服务，不能让浏览器直接拿服务器路径加载。
