# 多源处理产物与进度联动体验设计

## 目标

让用户在多源数据处理过程中，能够在每个阶段完成时立即看到该阶段产生的结果，并理解“当前正在做什么、已经做完什么、产出了什么、耗时多久”。现有任务状态、阶段状态、重试、取消、最终 ZIP 下载语义保持不变。

## 现状与问题

当前系统已经具备基础链路：后端 `/processing-tasks/{taskId}/progress` 返回阶段和产物，前端按 `stageId` 将产物挂到阶段，并支持展开、图片预览、单产物下载和最终 ZIP 下载。

但链路仍有几个体验缺口：

- 后端进度 DTO 当前只返回产物类型、URI、校验和，领域层已有的文件大小等信息没有完整透传。
- 阶段只返回状态和错误，缺少开始时间、结束时间、耗时、阶段职责和声明输出摘要。
- 产物虽然与阶段关联，但用户需要主动展开，无法明显感知“刚刚生成了什么”。
- 预览能力主要依赖 URI 后缀判断，缺少后端提供的媒体类型和预览能力声明。
- 失败信息没有和该阶段的输入、输出及已生成产物形成上下文关联。

## 设计原则

1. 阶段状态仍以数据库中的 `rs_task_stage` 为准，产物仍以登记后的 Artifact 为准，前端不推测或伪造完成状态。
2. 一个阶段完成后立即展示其产物；未完成阶段不显示虚假的产物结果。
3. 默认信息面向业务用户，技术细节放到可展开的诊断区域。
4. 大型科学文件不强行浏览器内打开，提供安全下载和元数据；图片、预览图和 JSON 报告优先支持在线查看。
5. 通过可选字段扩展现有进度接口，兼容旧任务、旧计划和旧客户端。

## 用户体验

### 阶段时间线

任务进度弹窗保留总进度条和阶段时间线。每个阶段行包含：

- 阶段名称和面向用户的职责说明，例如“辐射定标”“标准产品生成”“RGB 融合”。
- 状态：等待执行、正在执行、已完成、执行失败、需要重新执行。
- 已耗时；运行中显示实时耗时，完成后显示总耗时。
- 输入数量和产物数量，例如“输入 2 个 · 产物 1 个”。
- 阶段完成后显示“刚生成”提示，提示只在该阶段首次从未完成变为完成时出现。

### 自动展开策略

- 当前刚完成的阶段自动展开产物区，并将焦点/滚动位置移动到该阶段。
- 之前阶段保持用户当前的展开或折叠状态。
- 如果用户正在查看产物预览，不因轮询刷新强制关闭预览或重置滚动位置。
- 同一阶段重复轮询不会重复触发“刚生成”动画或通知。

### 产物卡片

每个产物卡片显示：

- 文件名和产物类型的中文说明。
- 文件大小、保留级别（中间产物/最终产物）和校验和摘要。
- 可用操作：预览、下载；不可下载时说明原因。
- 新生成产物显示“新生成”标记。

交互规则：

- PNG/JPEG/WebP/GIF 和后端声明可预览的媒体类型支持在线预览。
- JSON 报告以格式化文本或结构化摘要预览。
- COG、NetCDF、Parquet、HDF 等大文件显示元数据并下载，不直接嵌入浏览器。
- 产物下载继续走现有授权接口，不暴露未经授权的存储路径。

### 失败与诊断

失败阶段默认显示：

- 可读错误原因。
- 阶段已处理的输入数量和已生成产物数量。
- 重试按钮（沿用现有失败/恢复中限制）。

“诊断信息”折叠区可显示：

- 后端错误码、执行 ID、尝试次数。
- 阶段输入/输出类型摘要。
- 需要时显示受控的 Worker 诊断消息；不默认展示完整原始日志。

## 后端接口契约

继续使用现有进度接口：

`GET /api/multisource/processing-tasks/{taskId}/progress`

在现有字段上增加可选信息：

```json
{
  "stages": [{
    "stageId": 101,
    "stageKey": "WRITE_FY4B_STANDARD_COG",
    "status": "SUCCEEDED",
    "attempt": 1,
    "executionId": "exec-01",
    "startedAt": "2026-09-10T01:10:00Z",
    "finishedAt": "2026-09-10T01:10:42Z",
    "durationMs": 42000,
    "description": "生成标准 COG 产品",
    "declaredOutputs": ["FY4B_VIS_NIR_1000M_COG"],
    "errorCode": null,
    "errorMessage": null
  }],
  "artifacts": [{
    "stageId": 101,
    "type": "FY4B_VIS_NIR_1000M_COG",
    "uri": "rs://...",
    "checksum": "sha256:...",
    "sizeBytes": 12345678,
    "retention": "FINAL",
    "downloadable": true,
    "mediaType": "image/tiff",
    "previewable": false,
    "displayName": "FY4B_VIS_NIR_1000M_COG.tif"
  }]
}
```

兼容规则：

- 新字段全部可选；旧任务没有时间、大小或媒体类型时，前端回退到现有展示逻辑。
- `durationMs` 可由阶段执行上下文的开始/结束时间计算；运行中阶段由前端使用当前时间估算展示，但不得写回后端。
- `declaredOutputs` 来自任务的 plan snapshot，不由前端根据产物数量推断。
- `mediaType`、`previewable` 和 `displayName` 由后端根据登记产物和安全文件规则生成；前端仍保留扩展名回退判断。
- 现有产物下载授权和最终 ZIP 接口不变。

## 前端模块边界

### 进度状态模型

扩展 `ExecutionProgressStage` 和 `ExecutionProgressArtifact` 类型，增加可选字段；在 `processingRunState.ts` 增加：

- 阶段完成边沿检测，区分首次完成和已完成的轮询刷新。
- 阶段耗时格式化。
- 产物展示分类和预览策略。
- 阶段输出摘要与实际产物的关联函数。

### 任务进度弹窗

`TaskProgressDialog.vue` 只负责展示和事件派发，不负责推断后端状态。父组件负责：

- 保存阶段完成边沿状态。
- 维护自动展开目标和用户手动展开集合。
- 维护预览、下载和诊断面板状态。
- 在新阶段完成时保留现有用户交互上下文。

### 产物预览

沿用现有 Blob 下载/预览流程，增加 JSON 报告和后端 `previewable` 字段支持。预览失败时显示非阻塞错误提示，并允许继续下载。

## 数据流

```text
Worker 完成阶段
  -> 后端校验并登记 Artifact
  -> /progress 返回阶段状态 + Artifact 元数据
  -> 前端轮询比较前后快照
  -> 当前阶段从 RUNNING/WAITING 变为 SUCCEEDED
  -> 自动展开该阶段
  -> 显示“刚生成”产物卡片
  -> 用户预览或下载
```

如果阶段失败：

```text
阶段 FAILED
  -> 显示可读错误 + 输入/产物摘要
  -> 保留已有产物
  -> 提供重试
```

## 测试与验收

### 后端

- 进度 DTO 正确透传阶段时间、执行 ID、产物大小、保留级别和下载标志。
- 旧任务/旧计划在缺少新增字段时仍能返回合法响应。
- 阶段失败时不伪造产物；阶段成功时产物均归属正确 `stageId`。
- 产物元数据不泄漏未授权的物理路径。

### 前端

- 阶段完成边沿只触发一次自动展开和“刚生成”标记。
- 新阶段完成时，之前阶段的用户展开状态保持不变。
- 轮询刷新不关闭正在进行的预览。
- 图片和 JSON 进入预览，大文件进入下载；后端字段缺失时扩展名回退仍可用。
- 阶段计数、百分比、重试和最终 ZIP 行为保持现有测试结果。

### 真实验收

至少用 HY‑1C、FY‑3H、FY‑4B、GF‑6、HY‑2D 各创建一个新任务，逐阶段核对：

1. 阶段完成时间与 UI 状态变化一致。
2. 每个阶段的实际产物出现在对应阶段下。
3. 可预览产物能立即预览，大文件能下载。
4. 内部阶段不产生额外的用户可见计数。
5. 失败阶段显示原因且不会把下游阶段标为成功。

## 交付范围

第一期包含进度接口元数据补齐、阶段自动展开、产物卡片增强、图片/JSON 预览和诊断摘要；不包含完整 Worker 原始日志检索、在线 GIS 栅格渲染器或新的独立产物管理页面。若后续需要跨任务检索和长期资产管理，再单独设计产物中心。
